# 开发构建与磁盘空间规约

本规约适用于本仓库的 Rust/Tauri 开发、测试、离线验证与 macOS 打包。目标是在不削弱产品契约和验收门禁的前提下，避免 `src-tauri/target` 因历史中间产物无限增长。

## 产物边界

- `src-tauri/target`、`dist` 和 `参考/iina/build` 均为可重建产物，不得提交到 Git。
- `参考/iina` 是 IINA 1.3.5 产品契约，不得以节省空间为由整体删除。
- `src-tauri/target/release/bundle` 中的当前 App/DMG 是本地打包验收证据。常规空间清理必须保留该目录；删除 release 产物前必须明确确认其已不再需要，或已复制到项目目录外。
- `.git`、`参考/iina/.git`、`参考/iina/deps` 不是构建缓存，不得纳入常规清理脚本。

## Cargo profile 规则

- macOS 桌面程序仅生成被主程序实际链接的 `rlib`；不得在没有移动端或外部 FFI 消费方的情况下恢复 `staticlib`/`cdylib`。
- dev profile 保留项目代码的行级调试信息，第三方依赖关闭调试符号。
- test profile 必须关闭增量编译，避免完整验证为 `iima_lib` 留下多代大型增量图。
- `npm run verify:offline` 中的 Cargo 命令必须显式使用 `CARGO_INCREMENTAL=0`。不得为了节省空间删除该验证链中的 `cargo test` 或 `cargo check --all-targets`。
- 如需临时调试第三方 Rust 依赖，可通过命令行或本地未提交配置提高调试级别；不得把全依赖完整调试符号作为仓库默认值。

## 空间检查与清理

日常检查：

```bash
npm run cargo:space
```

安全清理预览：

```bash
npm run cargo:space:clean:dry-run
```

确认后清理 debug/test 产物：

```bash
npm run cargo:space:clean
```

清理脚本只允许删除仓库根目录下解析得到的 `src-tauri/target/debug` 精确路径，以及切换为仅生成 `rlib` 前遗留的四个精确文件：release 根目录及其 `deps` 目录中的 `libiima_lib.a`、`libiima_lib.dylib`。脚本必须保留 `src-tauri/target/release/bundle` 以及其他 release 产物。脚本默认执行预览；只有显式 `--apply` 才能删除。

空间阈值：

- 小于 8 GiB：正常，无需处理。
- 8–12 GiB：警告，检查近期是否存在频繁 feature/toolchain 切换。
- 大于 12 GiB：建议在当前开发任务完成后清理。

清理后第一次 Rust 构建会变慢，这是重新生成依赖和项目产物的正常成本，不能据此恢复无限增长的缓存策略。

## 配置变更门禁

修改 Cargo profile、crate type、features、target 目录或清理策略后，至少执行：

```bash
npm run cargo:space
cargo check --manifest-path src-tauri/Cargo.toml --offline --all-targets --features macos-cli
```

涉及 `crate-type`、release profile 或打包路径时，还必须执行：

```bash
npm run verify:offline
npm run package:mac
```

并确认主程序、`iina-cli`、App bundle、签名和 DMG 门禁仍然通过。空间优化不得降低 `docs/replication/README.md` 和验收矩阵规定的验证强度。
